## Exact secrets schema

The operator-created /home4/dltsin/fila-staging-private/secrets/staging-secrets.json must be a UTF-8 JSON object without a BOM, with exactly these two keys:

```json
{
  "databasePassword": "EXISTING_STAGING_DATABASE_PASSWORD",
  "appKey": "EXISTING_OR_SEPARATELY_APPROVED_NEW_STAGING_APP_KEY"

```

These are explanatory placeholders, not values to upload. Both values are strings; password is nonempty; key is at least 32 bytes; neither contains NUL; total file size must not exceed 8192 bytes. JSON escaping must preserve the password exactly. No database identity, origin or Wi-Fi setting belongs in this file: those are pinned in config.local.php.

Reuse an existing staging key if one exists. Only if no key exists and new-key provisioning is explicitly approved, generate 32 cryptographically secure random bytes and encode them as 64 hexadecimal characters (256 bits). Use a trusted local confidential directory with owner-only ACLs, outside the project, source control and sync folders. .NET RandomNumberGenerator.GetBytes supplies cryptographically strong bytes: https://learn.microsoft.com/en-us/dotnet/api/system.security.cryptography.randomnumbergenerator.getbytes . Never use Get-Random, timestamps or a human-created string.

Planned local PowerShell method below is NOT executed. It prompts for the existing staging password without echo, generates a key only in memory, writes the combined JSON once using CreateNew (never overwrites an existing file), and prints neither secret. Replace the destination with an existing, ACL-restricted local directory first. Do not run inside a debugger or transcript/session-recording environment. Do not include literal secrets in the script.

```powershell
$destination = 'C:\CONFIRMED_PRIVATE_DIRECTORY\staging-secrets.json'
$secretInput = Read-Host 'Existing staging database password' -AsSecureString
$generator = [Security.Cryptography.RandomNumberGenerator]::Create()
$randomBytes = New-Object byte[] 32
$stream = $null
$writer = $null
try {
    $generator.GetBytes($randomBytes)
    $newKey = [BitConverter]::ToString($randomBytes).Replace('-', '').ToLowerInvariant()
    $existingPassword = ([PSCredential]::new('staging', $secretInput)).GetNetworkCredential().Password
    if ([string]::IsNullOrEmpty($existingPassword)) { throw 'Password is required.' }
    $json = @{ databasePassword = $existingPassword; appKey = $newKey } | ConvertTo-Json -Compress
    $stream = [IO.File]::Open($destination, [IO.FileMode]::CreateNew, [IO.FileAccess]::Write, [IO.FileShare]::None)
    $writer = [IO.StreamWriter]::new($stream, [Text.UTF8Encoding]::new($false))
    $writer.Write($json)
} finally {
    if ($writer) { $writer.Dispose() } elseif ($stream) { $stream.Dispose() }
    $generator.Dispose()
    [Array]::Clear($randomBytes, 0, $randomBytes.Length)
    $secretInput.Dispose()
    $newKey = $null; $existingPassword = $null; $json = $null
}
```

In-memory .NET strings cannot be guaranteed erased; run on a trusted workstation. Upload only through authenticated TLS cPanel to the private destination. Set server permissions immediately and preserve a protected recovery copy. Do not display the JSON, screenshot it or send it through chat/support. Generation is not a password rotation, but creating a new app key is still a separately approved credential-provisioning action.
